Meta-orchestration for scientific agents

A conductor for your lab's agents.

Your agents already know the science. Getting them to work together is the hard part. As a workflow grows and more agents join, costs multiply and agents work at cross purposes. One step's error flows into the next, and an agent can report success without the evidence to support it. On sequential work, a team often does worse than a single agent, and a crash midway can repeat an experiment that cannot be undone.

MAESTRO designs how your agents work together. It turns a research request into a plan of steps, agents and checks, and runs that plan within a fixed budget. It accepts a result only when checks that run outside the models pass on the tools' evidence.

Meta-orchestration

Above your agents, not in place of them.

Each agent keeps its own goal, tools and knowledge. MAESTRO engineers the graph of steps and agents between them, runs it, and checks the result.

Accepts requests from any agent

Agents send signed requests. Every job goes into one queue, and you approve each plan once.

Engineers the graph between agents

Each agent keeps its own goal, tools and knowledge. MAESTRO never sets the goal.

Connects instruments and agents

Instruments and simulations connect over MCP, including long-running tasks. Steps go to remote agents over A2A, each identity verified.

Delivers checked answers

An answer goes back to the agent that asked or on to another. An answer that failed its checks is never delivered.

Allocates resources across agents

Spending caps per agent by week or month, priorities so one campaign cannot starve another, and one safe pause for everything.

Delegates to other orchestrators

A whole step goes to another orchestrator with its own budget, deadline and the checks its result must pass.

How it works

One plan, designed and then run, with every step checked.

A request in plain words becomes a whole plan. You approve it once, and it runs with every step checked.

A whole plan from plain language

Five blocks: a step, parallel work over many items, a decision, a bounded loop and an approval.

Up to three plans, honestly compared

Careful, balanced and fast, each with a cost ceiling, a time estimate and a count of irreversible calls. The single-agent plan is always costed at the same budget.

Three ways to design

From a predictive model, by reusing verified plans, or by tree search over simulated copies of the tools along a cost and pass-rate trade-off.

Team wiring that earns its links

Lead and workers, chain, debate, review or vote. Links that add nothing are pruned.

Staffed and batched to fit

A model chosen for each step, and work batched to fit the capacity each instrument declares.

Checked as it is drawn

Every block is checked in code as it is drafted, and the whole plan is validated before anything runs.

Adaptive execution

A plan that changes as the evidence does.

Between steps and rounds, MAESTRO repairs, redraws or stops early, and every change is held to the same rules as the plan you approved.

Steers between steps and rounds

MAESTRO first tries a local edit to the part that failed, then a redraw of the rest of the plan, or stops early with the best result so far.

Triggered by evidence

Failed checks, results out of range, a forecast budget overrun, an unreachable tool, diminishing returns, or a note from you or the agent that sent the job.

Three rules, checked in code

The approved answer and its checks stay, finished work is untouched, and the new plan passes the same validation. A change beyond what you approved asks you first.

A failed step becomes its own plan

A step that keeps failing is broken into a smaller plan, up to three levels deep, within the budget that step had left.

Long campaigns

Plans that run at the pace of experiments.

A campaign can last weeks. MAESTRO waits as long as the lab does, without holding anything while it waits.

Waits as long as the experiment

A job waiting on a long experiment or simulation is suspended and holds no resources. It wakes on schedule and resumes from a checkpoint, at the same cost on day 20 as on day 1.

Survives restarts and upgrades

Each campaign keeps the plan it started with. Nothing is lost and nothing is sent twice.

The best result so far, every round

After each round, the best answer yet is held to the same checks as the final one.

Problems become questions

An expired sign-in or a retired model becomes a question for you or a change of model, not a failure.

Respects instrument capacity

A tool declares how many runs it takes at once, for example four reactors. Plans batch to fit.

Weeks in seconds, for testing

A simulated clock compresses a whole campaign into seconds, so a plan can be rehearsed before the lab is booked.

Integrity

Results you can audit, trace and retract.

The checks, budgets and policies live outside the models, and every result records where it came from.

A complete journal

Every model call, tool call and verdict is journalled, so a run resumes without repeating model calls.

Standard provenance

Lineage exports as W3C PROV, and traces as OpenTelemetry.

Retractions propagate

Withdraw a measurement and every result derived from it is flagged, with re-runs proposed.

Verification

Evidence before acceptance

A result is accepted only with evidence that cites the tool outputs behind each claim.

Rule-based checks first

Eleven check types compare an answer with your tables, ranges and references. A model judge runs only after they pass.

Checks are tested too

Every check is run against a deliberately wrong answer, to show that it catches it.

The judge is measured

A model judge's agreement with expert verdicts is reported as a rate and as Cohen's κ.

Resistance to injection, measured

Canary runs plant instructions in tool results and show whether an agent follows them.

Your own verifiers

Bring deterministic or simulation-based verifiers. A check can route the next step: explore, replicate or finish.

Safety and governance

Budgets reserved up front

Tokens, cost, time, tool calls and instrument hours are reserved before work starts. Stopping is decided in code, not asked of the model.

Irreversible means irreversible

Every tool declares its side effects. Irreversible actions need your approval and run at most once. An uncertain outcome comes to you.

Policy at every effect

A Cedar policy governs every action with effects, under four risk tiers. At high risk, runs are repeated, must agree, and the result is signed.

Signed and pinned

Requests and results are signed with Ed25519, every message carries a trust label, and tool definitions are pinned.

Sandboxed code

Code runs in a sandbox whose isolation from the network and file system is verified before use.

Defence in depth

A quarantined reader, taint tracking and an attack suite guard against prompt injection; circuit breakers and fault injection test the rest.

Automation

Routine work runs itself, under your control.

Schedules and events

Jobs repeat on a schedule, or start when a file changes, new data arrives or a webhook is called.

Costs nothing when nothing is new

A repeating job makes no model calls without new inputs, and remembers the items it has handled.

Autonomy is earned

Every automatic action starts off. Write access comes only after verified report-only runs, and is withdrawn after failures.

Prompts that improve on evidence

Judge questions and instructions are reworded and tested on held-out cases. You adopt or roll back each change.

Portable loops

A loop exports as LOOP.md and SKILL.md, with health monitoring, a watchdog and notifications.

A console built for answers

Every job in one list, the answer first, a live plan graph and follow-up questions beside each job.

Learning

A designer that improves on its own record.

MAESTRO learns from every job it runs, and every improvement must prove itself on a test it never sees.

Improves its own designer

Without training, lessons from each round inform the next design. A new version is adopted only after it wins a hidden held-out test twice at the same budget.

Trains plan models on its own data

A small model of plan structure, then a fine-tuned language model, trained only on data MAESTRO generates and used only when it beats the prompted designer.

Benchmarked in the open

The RSI Bench and RSI-Index public benchmarks, and MAESTRO's own hidden test, run from the console.
